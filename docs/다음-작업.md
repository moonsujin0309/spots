순서대로. 1번이 끝나야 나머지가 의미 있다.

1. **Supabase 프로젝트 생성**
   - ⚠️ 리전을 **서울(ap-northeast-2)** 로. **생성 후 변경 불가**이고,

   - ⚠️ `service_role` 키는 절대 넣지 말 것. 공개 저장소다

2. **카카오 개발자 콘솔**
   - 카카오 로그인 활성화 + Redirect URI 등록 (Supabase 가 알려주는 주소)

     - 지도: 플랫폼 > Web > 사이트 도메인
     - 공유: 제품 링크 관리 > 웹 도메인

3. **도메인 구매 + 호스팅 이전** (GitHub Pages → Vercel 또는 Cloudflare Pages)

4. **알바 계약서 서명** — 저작권 양도 조항이 핵심. 작업 시작 **전에** 받아야 한다

5. **법률 검토** — 약관 · 개인정보 처리방침 · 계약서

## 3. 붙인 다음 첫 확인 (한 바퀴)

이 순서로 돌려 보면 연동이 제대로 됐는지 다 걸린다.

1. 카카오 로그인 → 프로필에 내 닉네임이 뜨나
2. 루트 만들기 → 사진 첨부 → 게시 → **다른 브라우저(로그아웃 상태)에서 그 링크가 열리나**
3. 저장·좋아요·팔로우 → 새로고침 → 그대로 남아 있나
4. **다른 기기에서 로그인** → 저장함이 따라오나
5. 장소 상세 "정보가 달라요" → Supabase 의 `place_reports` 에 행이 들어왔나
6. 프로필 → 회원 탈퇴 → 내 루트가 사라지고 남의 루트는 남아 있나 (테스트 계정으로)

막히면 브라우저 콘솔과 Supabase 대시보드의 Logs 를 같이 본다.
대부분은 RLS 정책 아니면 카카오 Redirect URI 다.

## 5. 검증 환경 만드는 법

이 저장소는 테스트 프레임워크가 없다. 대신 이렇게 확인했다. 다음에도 같은 방법을 쓰면 된다.

### JS 문법

```bash
python3 -c "
import io; s=io.open('index.html',encoding='utf-8').read()
a=s.rfind('<script>'); b=s.rfind('</script>')
io.open('/tmp/app-body.js','w',encoding='utf-8').write(s[a+8:b])"
node --check /tmp/app-body.js
```
`rfind` 를 쓰는 이유 — 파일 맨 위에 GA4 스크립트가 따로 있어서 첫 `<script>` 부터 잡으면 안 된다.

### 스키마 · 쿼리 (로컬 PostgreSQL)

Supabase 전용 객체는 스텁으로 대체한다.

```bash
D=/var/lib/postgresql/check          # postgres 홈 아래여야 권한이 맞다
mkdir -p $D && chown postgres:postgres $D
su postgres -c "/usr/lib/postgresql/16/bin/initdb -D $D -A trust -E UTF8 --locale=C"
su postgres -c "/usr/lib/postgresql/16/bin/pg_ctl -D $D -o '-k /tmp -p 55432 -c listen_addresses=' -l $D/log start"
su postgres -c "psql -h /tmp -p 55432 -qd postgres -c 'create database spots'"
```

스텁 (schema.sql 보다 먼저 실행):
```sql
create schema if not exists auth;
create table if not exists auth.users (id uuid primary key default gen_random_uuid());
do $$ begin if not exists (select 1 from pg_roles where rolname='authenticated')
  then create role authenticated; end if; end $$;
create or replace function auth.uid() returns uuid language sql stable
  as $$ select nullif(current_setting('app.uid',true),'')::uuid $$;
```

로그인한 사용자를 흉내낼 때는 `set app.uid = '<uuid>';` (트랜잭션 밖에서는 `set local` 이 안 먹는다).
`docs/storage.sql` 은 Supabase 전용이라 여기서 돌지 않는다 — 검증 대상이 아니다.

### 화면 (Playwright)

```bash
cd /home/user/spots && python3 -m http.server 8123 &
npm i playwright --no-audit --no-fund
```
```js
chromium.launch({ executablePath:"/opt/pw-browsers/chromium", args:["--no-sandbox"] })
```
설치된 playwright 가 기대하는 브라우저 빌드 번호와 `/opt/pw-browsers` 에 있는 것이 달라서
`executablePath` 를 직접 줘야 한다. `npx playwright install` 은 하지 말 것.

서버를 켠 상태를 흉내내려면 페이지 안에서 `sb` 를 프록시로 채운다:
```js
const chain = new Proxy(Promise.resolve({data:[],error:null}), {
  get(t,k){ if(k==="then") return t.then.bind(t); if(k==="catch") return t.catch.bind(t); return ()=>chain; }});
sb = { from:()=>chain, auth:{ getSession:()=>Promise.resolve({data:{session:null}}), onAuthStateChange:()=>{} } };
ME = { id:"u1", nick:"테스트", avatar:"🙂", role:"user" };
```
`sb={}` 만 넣으면 `sb.from is not a function` 으로 터진다.

## 6. 이번에 실제로 걸렸던 것들

같은 데서 또 막히지 않게 남긴다.

| 증상 | 원인 |
|---|---|
| 시드 136개 중 13%만 검수 통과 | "스팟 간 도보 15분" 기준이 틀렸다. 앱은 구간 거리로 이동수단을 자동 배정한다(1.2km↓ 도보 / 3km↓ 버스 / 7km↓ 지하철). 실측 구간의 46%가 도보 범위를 넘는다 |
| 지역별 루트 수가 부풀려짐(혜화 20건 → 실제 4건) | `areas` 에 `routes` 와 `places` 를 한꺼번에 join 해서 4×5 의 곱이 됐다. 세는 것이 둘이면 각각 센다 |
| 탈퇴가 "routes 가 참조 중"이라며 통째로 막힘 | 삭제 순서가 아니라 **외래키의 on delete 규칙**이 동작을 정한다. `auth.users` 를 지우면 profiles 가 cascade 되는데 routes 가 그걸 붙잡는다 |
| 검수기가 앱에서 입력도 안 되는 제목을 통과시킴 | 검수 상한 40자, 앱 입력 상한 25자(`TITLE_MAX`). 두 값은 같아야 한다 |
| 제보 폼을 눌렀는데 반응이 없어 보임 | 폼이 화면 밖에서 열렸다. `scrollIntoView` 로 데려간다 |
